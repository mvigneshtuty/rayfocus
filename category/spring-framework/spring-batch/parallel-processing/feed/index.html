For introduction on how to write a Spring Batch job, you can refer the previous post which provides details on how to read files from S3 bucket.

It’s all based on your use case

Spring Batch provides lot of options to implement a Job with parallel processing. But it does not mean you must choose one of them. Your decision to use parallel processing should be driven by your use case. Most of the times, a single threaded Job would be suffice for many of the use cases. So, first try out with a single threaded Job. If that is not enough and you have valid point for parallel processing, then pick one of the scaling options provided by Spring Batch.

Different types of Scaling options
  1. Multi threaded step
  2. Parallel step
  3. Asynchronous Item processor/Item writer
  4. Remote partitioning
  5. Remote chunking

Even in the previous post, we have used one of the scaling technique “Asynchronous item processor/writer”. But we will go through the details of that scaling option in a separate post.

In this post, we will go through the “Multi threaded step” scaling technique.

Multi threaded step

The configuration to achieve the multi threaded step is straight forward. In general, Spring Batch process the record in chunks.

Let’s say the chunk size is 100.
With single threaded step(which is the default), the first 100 record is processed. Once completed, the next 100 and goes on.
With multiple threaded step of 2 threads for example, two chunks are processed in parallel i.e total 200 records. Once competed, it continues to pick the next two chunks and goes on.

Adding task executor to the step makes it multi threaded.

@Bean
    public Step dataProcessStep() throws Exception {
        Step step = this.stepBuilderFactory.get("dataProcess-step")
                .<TransactionData, TransactionData>chunk(chunkSize)
                .reader(dataReader())
                .faultTolerant().skipLimit(100)
                .processor(dataProcessor(null))
                .writer(dataWriter(null))
                .taskExecutor(taskExecutor())
                .build();
        ((TaskletStep) step).setStepExecutionListeners(new StepExecutionListener[]{
                stepExecutionListener()
        });
        return step;
    }

Task executor config

@Bean
    public TaskExecutor taskExecutor()
    {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(threadPoolSize);
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        executor.setThreadNamePrefix("exec-");
        return executor;
    }
